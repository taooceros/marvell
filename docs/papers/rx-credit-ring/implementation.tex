\section{Implementation and Testbed}\label{sec:impl}

We implement \sys{} in Rust on unmodified PCIe Gen5 server hardware paired with a commercial 100GbE programmable SmartNIC and a second physical 100GbE traffic peer.

\paragraph{Hardware platform.}
Table~\ref{tab:testbed} summarizes our two-server testbed. The receiver host is an Intel Xeon Gold 6438M (Sapphire Rapids) running Linux 6.17 with full hardware IOMMU enabled in scalable mode, a 60~MiB 15-way shared L3 cache (default 2-way DDIO = 8~MiB), 2~MiB hugepages pinned on NUMA node~1, and two populated DDR5 channels ($\sim$60~GB/s). We pin the host receive core at 3.90~GHz (performance governor) and Socket-1 uncore/mesh at 2.20~GHz to eliminate dynamic frequency noise. The active NIC is a Marvell OCTEON~10 CN106 100GbE SmartNIC attached over PCIe Gen5 $\times$4, featuring 24 ARM Neoverse-N2 cores at 2.00~GHz, a 48~MiB shared on-NIC L3 cache (128~B lines), 48~GB of 6-channel on-NIC DDR5, and four native DMA virtual functions (DPI VFs). A second physical server carrying an NVIDIA ConnectX-5 100GbE NIC connects directly to the CN106 over a 3~m passive copper DAC (no-FEC).

\paragraph{Datapath implementation details.}
On the NIC, \sys{} maps the host's IOMMU-translated 256~KiB hot ring through an outbound write-combining PCIe window (with per-cell write ordering enabled so every 64~B cell exits as an ordered 64~B TLP without cross-cell merging). For large 326--4096~B unidirectional receive frames (\S\ref{sec:eval-rx}), the NIC issues asynchronous posted DMA writes via four native DPI VFs into compact per-lane host receive rings ($\le$2~MiB aggregate across four lanes), paced by batched credits. Host-to-NIC credit updates (\texttt{TAKEN}) and small outbound RPC replies ride over a leased PCIe BAR4 MMIO window using 64-byte atomic writes (\texttt{MOVDIR64B}) on the host and explicit startup/teardown lease handshakes so the host never touches unmapped device memory. For large 1--4~KiB KV \texttt{GET} replies in \S\ref{sec:eval-rpc}, the host places reply values in a compact retained TX buffer pool (default 1,024 $\times$ 4~KiB slots = 4~MiB, versus 32,768 slots = 128~MiB in our cache-spill sensitivity control) read by the NIC via native DPI DMA. We also evaluate a hardened NIC-side Ethernet RX variant (\texttt{direct\_safe}) that eliminates cross-core atomic descriptor refills on the CN106 wire ingress while preserving full error-drop validation.

\paragraph{Engineering an ultra-fair descriptor-ring baseline.}
Comparing a new receive interface against a poorly configured stock DPDK driver can exaggerate software savings. Using the exact same CN106 hardware and host core, we first ran a 126-run single-variable ablation on the vendor's PCIe descriptor-ring driver (SDP) at 4~KiB and 1.0~M~reqs/s to strip out every avoidable driver artifact:
\begin{enumerate}
  \item Stock SDP consumes \textbf{3,860~cycles/pkt} (99.0\% of one 3.90~GHz core).
  \item Replacing MMIO doorbell reads with in-memory completion polling cuts cost to \textbf{2,348~cycles}; enabling zero-copy in-place buffer reuse lowers it to \textbf{1,489~cycles}, but exposes synchronous packet-tail spinning on 54.8\% of packets.
  \item Converting tail verification to non-blocking asynchronous polling eliminates all late-tail stalls (54.8\% $\to$ 0.0\%) and saves 459~cycles, dropping cost to \textbf{1,030~cycles}.
  \item Enabling in-memory ring-index updates (ISM), shrinking the host receive ring to fit inside DDIO (512 descriptors), and separating TX/RX pools raises DDIO hit rate from \textbf{45.2\% to 100.0\%} and cuts host DRAM writes by \textbf{76$\times$} (35.6 $\to$ 0.47~lines/pkt; 61$\times$ to 0.58~lines/pkt on full \texttt{SDP fair-full}), yielding our final \texttt{SDP fair-full} baseline at \textbf{1,010~cycles/pkt} (857~cycles at batch $B{=}8$), compared to \textbf{508~cycles/pkt} (461 at $B{=}8$) for the full DirectPush datapath incorporating \sys{} on RX.
\end{enumerate}
On the same card at 64~B ($W{=}1$), DirectPush+\sys{} lowers unloaded round-trip latency from 4.635~$\mu$s on tuned SDP to 0.885~$\mu$s (5.24$\times$). All dual-host 100GbE evaluations in \S\ref{sec:eval-rx}--\S\ref{sec:eval-rpc} compare against this tuned asynchronous SDP baseline rather than stock SDP.

\paragraph{Verification discipline and boundaries.}
Every run across all 1,089 archived experiments enforces end-to-end sequence and trailer checks (zero lost, corrupted, or torn messages), zero host page faults, pinned clocks verified per run, zero EDAC/AER hardware errors, and 100\% non-multiplexed hardware performance counters (Intel host L3 offcore, CHA DDIO hit/miss, IIO inbound/outbound PCIe bytes, and IMC DDR5 CAS counters; ARM CN106 core, L3 TAD, and 6-channel DDR5 counters). Throughout \S\ref{sec:eval}, we report medians across interleaved $n{=}3$ (or pooled $n{=}6$) trials and explicitly separate channel-independent on-die invariants from platform-specific memory-channel effects.
