## B01: 真实轮询代码怎么写：零锁分片与跨步扫描 (59.7 s)

*Source: `mrv245_host.rs:765-776 · mrv245_card.rs:962-1037`*

- **[0.45–8.57s]** (`MRV-258`) 主机把 **64 字节**请求经 `BAR4` 写进网卡共享环，为什么免门铃轮询会撞上**两面不同的硬件墙**？
  - *Spoken*: 主机把六十四字节请求通过 bar 四写进网卡共享环，为什么免门铃轮询会先后撞上两面完全不同的硬件墙？
- **[8.77–18.42s]** (`mrv245_host.rs:771-776`) 先看主机热循环 `mrv245_host.rs`：每条 `Lane` 按 **128 字节步长**取槽，用 `MOVDIR64B` 原子推入 `BAR4` 槽 15。
  - *Spoken*: 先看真实的主机热循环代码。每条通道按一百二十八字节步长错开缓存行，用 move dir 六十四字节指令原子推入 bar 四槽十五。
- **[18.62–27.91s]** (`mrv245_host.rs:772-774`) 步长取 **128 字节**而非 64 字节，专门避开 `CN106` 128 字节缓存行的伪共享；发完即走，**零门铃、零 `SFENCE`**。
  - *Spoken*: 步长刻意取一百二十八字节，是为了避开 C N 一零六一百二十八字节缓存行的伪共享。写完即走，全程零门铃、零 S fence。
- **[28.11–37.08s]** (`mrv245_card.rs:962-972`) 卡侧 `mrv245_card.rs` 把 `H` 条 `Lane` 划给 `K` 颗卡核：每核起始 `next = lane_w + 1`，步长 `stride = K / H`。
  - *Spoken*: 再看卡侧代码。H 条独立通道均匀划给 K 颗卡核，每颗核从自己的编号加一起步，步长等于每通道核数 K 除以 H。
- **[37.28–48.11s]** (`mrv245_card.rs:962-972`) 以 `H = 1, K = 4` 为例：0 号核扫 `1, 5, 9`，1 号核扫 `2, 6, 10`——槽位严格不交叠，**全程零跨核锁**。
  - *Spoken*: 比如单通道配四颗卡核，零号核只扫一、五、九号槽，一号核只扫二、六、十号槽。槽位严格不交叠，完全不需要任何跨核锁。
- **[48.31–58.67s]** (`mrv245_card.rs:1001-1037`) 每格用头尾双序号 `words[0]` 与 `words[7]` 校验完整性，命中即回包。代码极简，可一上默认内存映射就锁死在 **13.5 M/s**。
  - *Spoken*: 卡核直接比对首尾两个序号字段校验完整性，命中就回包。这套代码极其干净，但一跑在默认内存映射上，吞吐立刻被锁死在十三点五百万包每秒。
## B02: 第一道墙：Normal-WB 嗅探死锁与历史 175 Mpps 真相 (76.3 s)

*Source: `MRV-235/245 runs.jsonl · MRV-155/177/196`*

- **[0.45–9.45s]** (`MRV-235 / MRV-258`) 默认映射是 `Normal-WB`：卡核只要读过一个槽，硬件就会把这条缓存行拉进核私有 **`L1D / L2`**。
  - *Spoken*: 问题出在默认的 Normal W B 映射。卡核只要读过某个槽，硬件就会把这条缓存行搬进卡核私有的 L 一 D 和 L 二缓存。
- **[9.65–19.01s]** (`MRV-245 cl_wb_raw_k4_w256`) 下一圈主机经 `BAR4` 写新包进 **48 MiB `TAD`** 时，硬件被迫跨核发 **`0x58` 嗅探**，逐一作废卡核私有副本。
  - *Spoken*: 等环形队列绕回下一圈，主机再经 bar 四把新包写进四十八兆 T A D 时，硬件被迫跨核发出零 x 五八嗅探，去作废卡核私有的旧副本。
- **[19.21–29.66s]** (`MRV-245 cl_wb_raw_k4_w256`) 实测闭环 `K = 4` 每包触发 `0.99` 次 `l1d_refill` 和 **`1.96` 次 `0x58` 作废**，吞吐焊死在 **`13.53 M/s`**。
  - *Spoken*: 实测闭环四核下，平均每包触发零点九九次 L 一重填和一点九六次零 x 五八作废，读写在前沿死锁，吞吐被焊死在十三点五三百万包每秒。
- **[29.86–40.63s]** (`MRV-245 tx_wb_u1_h1_k4`) 哪怕切到单向宽窗硬扛，`Normal-WB` 也只跑 **`104.2 M/s`**，还把主机 `CHA` 拥塞顶爆至 **`546.2`**，重伤同机邻居。
  - *Spoken*: 哪怕切到单向宽窗硬扛，Normal W B 也只跑到一百零四点二百万包每秒，而且把主机 C H A 队列占用顶爆到五百四十六点二，直接拖垮同机邻居。
- **[40.83–50.78s]** (`MRV-258 #comment-6d928e2d`) 那以前用 `WB` 怎么跑出 **161–175 Mpps** 的？真相只有两条路——**绝不让卡核去轮询正在写的数据槽**。
  - *Spoken*: 这时候你一定会问，那以前用 W B 怎么跑到一百六十一到一百七十五百万包每秒的？真相很直白：全靠绝不让卡核去轮询正在写的数据槽。
- **[50.98–61.60s]** (`MRV-196 / MRV-245 tx_none`) 路一是**卡静默**（`tx_none`）：卡核压根不读，天然零嗅探，单核 **`161.7`**、双核 **`175.2 Mpps`**。
  - *Spoken*: 第一种情况是卡静默纯写测试，卡核压根不读数据环，一条都不进 L 一缓存，天然零嗅探，单核一百六十一点七、双核一百七十五点二百万包每秒。
- **[61.80–75.27s]** (`MRV-155 / MRV-177 / MRV-245`) 路二是 **128 格解耦批门铃 + 批尾 `SFENCE`**（`161.42 Mpps`）：卡核只盯门铃、时空错开，代价是 `W = 1` 固定慢 **`~190 ns`**。
  - *Spoken*: 第二种是解耦批门铃加批尾一次 S fence，实测跑出一百六十一点四二百万包每秒。主机写满一百二十八格再敲门铃，卡核只盯门铃不碰热槽，代价是空载延迟固定慢大约一百九十纳秒。
## B03: 破局：标准 Linux MT_NORMAL_NC 直读 48 MiB TAD (63.1 s)

*Source: `MRV-245/252 runs.jsonl · pgprot_writecombine (0x44)`*

- **[0.45–10.57s]** (`MRV-245`) 既想保留免门铃、免 `SFENCE` 的 `904 ns` 极致低延迟，又要彻底甩掉 `L1D / L2` 嗅探，解法藏在**标准 Linux 页表**里。
  - *Spoken*: 如果既想免门铃、免 S fence，保住九百零四纳秒的超低延迟，又要彻底甩掉 L 一和 L 二缓存嗅探，答案就在标准 Linux 页表属性里。
- **[10.77–21.13s]** (`mrv245_card.rs:3-10`) 零修改内核 `MAIR_EL1`，直接用标准 `pgprot_writecombine` 映射接收环——也就是 ARM64 的 **`MT_NORMAL_NC (0x44)`**。
  - *Spoken*: 完全不用魔改 M A I R E L 一寄存器，直接用内核自带的写合并页表属性，也就是 ARM 六十四标准的 M T Normal N C，编码零 x 四四。
- **[21.33–31.32s]** (`MRV-245 / MRV-252`) 卡核发起 `ldp q` 读取时，数据**直接绕过私有 `L1D` 与 `L2`** 落进向量寄存器，硬件永远不在核内留副本。
  - *Spoken*: 在 M T Normal N C 下，卡核发出 l d p q 指令时，数据直接绕过核私有的 L 一 D 和 L 二，落进向量寄存器，绝不在核心里留副本。
- **[31.52–42.27s]** (`MRV-245/252 ddr.reads_total`) 关键在于：它虽绕过 `L1 / L2`，在 `CN106` 上依然稳稳命中片上 **48 MiB `TAD` 共享 L3**，实测 **`DDR5 读 = 0.00`**。
  - *Spoken*: 最妙的是，它虽然绕过了 L 一和 L 二，但在 C N 一零六上依然稳稳命中片上四十八兆 T A D 共享缓存，实测 D D R 五内存读次数完全为零。
- **[42.47–51.14s]** (`MRV-245/252 core_pmu`) PMU 铁证如山：`l1d_refill` 从 `0.99` 归 **`0.00`**，`0x58` L2 作废从 `1.96` 归 **`0.00`**，第一道嗅探墙彻底消失。
  - *Spoken*: 硬件计数器铁证如山：L 一重填归零，零 x 五八作废彻底归零，第一道缓存嗅探墙瞬间烟消云散。
- **[51.34–62.14s]** (`MRV-245/252`) 免门铃单向吞吐原地直飙 **`159.9–174.1 M/s`**，空载 `W = 1` 仍稳守 **`904.5 ns`**——可一进闭环，第二道墙冒了出来。
  - *Spoken*: 于是免门铃单向吞吐直接飙到一百六十到一百七十四百万包每秒，空载延迟稳守九百零四点五纳秒。可一进闭环，第二道墙却突然冒了出来。
## B04: 第二道墙：什么是 EXLMN？闭环 + u4 为何雪崩至 17.6 M/s (85.0 s)

*Source: `marvell_cn10k_tad_pmu.c:304-306 · mrv252_card.rs:1162-1191`*

- **[0.45–11.27s]** (`marvell_cn10k_tad_pmu.c:285-306`) 先说大白话：**`EXLMN`** 不是玄学协议，它来自内核 `marvell_cn10k_tad_pmu.c`，全称 **`excluding MN`**（排除杂项节点）。
  - *Spoken*: 先把 E X L M N 讲透。它不是什么新协议，而是 C N 一零六内核 T A D 计数器的缩写，全称 excluding M N，意思是排除杂项控制节点。
- **[11.47–21.93s]** (`marvell_cn10k_tad_pmu.c:304-306`) `TAD` 的片上嗅探 `tad_snp_msh_out_any` 拆成 `mn`（TLB / 同步广播）加 **`exlmn`（事件 `0x16`：常规缓存行嗅探）**。
  - *Spoken*: T A D 往片上网格发出的嗅探拆成两半：M N 是 T L B 和同步广播，而 E X L M N 就是排除杂项后、所有针对普通缓存行的常规嗅探。
- **[22.13–34.04s]** (`MRV-252 k4_ow_u1_ldpq`) 单向宽窗 `W = 6144` 时，主机狂奔领跑数千格，卡核在安全后方读旧槽：**`EXLMN = 0.009 / 包`**，稳跑 **`159.9 M/s`**。
  - *Spoken*: 看单向宽窗 W 等于六一四四：主机不用等回包，领先卡核好几千格，卡核永远在安全后方消费，E X L M N 每包只有零点零零九次，稳跑一百六十百万包每秒。
- **[34.24–45.46s]** (`MRV-258`) 但进了闭环 `W = 256 / 512`，主机必须等回包、缓冲垫变薄，卡核瞬间**追平写入前沿**，撞上主机正在落盘的槽。
  - *Spoken*: 一进闭环 W 等于二五六或五一二，主机发满窗口就得停下来等回包，缓冲垫瞬间变薄，卡核追平写入前沿，和主机刚进来的写操作面对面撞上。
- **[45.66–57.87s]** (`mrv252_card.rs:1162-1191`) 此时 **`u4_ldpq`**（`8× ldp q`）一次齐射 `s0..s3`，往前偷看 **`3 × K = 12` 格未写空槽**；连 `adapt-*` 一命中也会切到 `u4` 中招！
  - *Spoken*: 更致命的是 u 四 l d p q：它一口气预读未来三个步长共十二格的未写空槽。就连带退避的 adapt 状态机，只要 s 零一命中也会立刻切进 u 四，照样中招。
- **[58.07–70.40s]** (`MRV-252 k4_cl_w256_u4_ldpq`) 穿透 `L1/L2` 的空读正面对撞 `PEM0` 入向写：`EXLMN` 飙升 **119×** 至 **`1.06 / 包`**，`tad_req_occ` 暴涨 **`7.0×`**！
  - *Spoken*: 这些绕过 L 一和 L 二直打 T A D 的未来空读，与主机 P E M 零入向写迎头相撞。E X L M N 飙升一百一十九倍到每包一点零六次，T A D 请求队列占用暴涨七倍。
- **[70.60–84.01s]** (`MRV-245/252`) **读撞写 → 写变慢 → 回包慢 → 主机发更慢 → 每包必撞**：正反馈雪崩把闭环锁死在 **`17.6–19.7 M/s`**（超配 `K = 8` 亦跌至 `16.3 M/s`）。
  - *Spoken*: 读撞写让写变慢，写变慢让回包变慢，闭环主机拿不到回包发得更慢，导致每包必撞。正反馈雪崩把吞吐一路按死在十七点六到十九点七百万包每秒，超配八核也一样跌到十六点三。
## B05: 真正解法与邻居边界：零前瞻 u1_ldpq + 信用窗 W ≤ 256 (72.7 s)

*Source: `MRV-245/252 runs.jsonl · mrv252_card.rs:1095-1102`*

- **[0.45–12.22s]** (`mrv252_card.rs:1095-1102`) 对比源码就一目了然：把 `u4_ldpq` 的 4 槽齐射换成零前瞻 **`static-u1q (u1_ldpq)`**，只用 `2× ldp q` 严格读当前格 **`s0`**。
  - *Spoken*: 对比源码就一目了然。把 u 四 l d p q 的四槽齐射换成零前瞻的 static u 一 q，只用两条 l d p q 严格读取当前槽位 s 零，绝不偷看后面的未写空槽。
- **[12.42–24.43s]** (`MRV-252 k4_cl_w256/512_u1_ldpq`) 绝不偷看 `s1 / s2 / s3` 后，同样 `K = 4, W = 256` 闭环，`EXLMN` 骤降 **`3.2×`**（`1.06 → 0.33 / 包`），`W = 512` 降到 `0.23 / 包`。
  - *Spoken*: 不偷看未来空槽之后，同样四核、窗口二五六的闭环，E X L M N 立刻骤降三点二倍，从一点零六降到零点三三次每包，五一二窗口更降到零点二三次。
- **[24.63–37.45s]** (`MRV-245/252`) 同一零门铃二进制一箭三雕：`W = 1` **`904.5 ns`**，单向 **`159.9 M/s (CHA 16.9)`**，闭环 **`61.4–75.8 M/s`**（`H = 2` 达 **`119.7 M/s`**）！
  - *Spoken*: 同一个免门铃、免 S fence 二进制直接一箭三雕：空载九百零四点五纳秒，单向一百五十九点九百万包每秒，闭环冲上六十一点四到七十五点八，双主机通道更达一百一十九点七百万包每秒。
- **[37.65–47.04s]** (`MRV-252 nb_k4_ow_*`) 实测同机邻居保护：`NC K = 4` 单向满速时，同 Socket 六核 **`STREAM`** 稳居 **`99.5%–100.0%`**，实现**零劣化**。
  - *Spoken*: 再看同机邻居实测：N C 四核单向满速跑时，同插槽六核 STREAM 内存带宽稳居百分之九十九点五到百分之百，对主机邻居几乎零干扰。
- **[47.24–58.77s]** (`MRV-252 nb_k8_ow_*`) 但边界必须诚实守住：一旦把卡核超配到 **`K = 8`**，主机 `CHA` 飙至 **`374–383`**，`6c STREAM` 实跌 **`-11.4% ~ -12.6%`**。
  - *Spoken*: 但工程边界必须守住：一旦把卡核超配到八核，主机 C H A 占用立刻飙升到三百七十四到三百八十三，同机六核 STREAM 实测下跌百分之十一点四到十二点六。
- **[58.97–71.66s]** (`MRV-252 k4_ol_40m/80m`) 且宽窗 `W = 6144` 部分负载下 `CHA` 仍会爬到 **`250–307`**——因此务必搭配**合理配核（`K = 2–4`）+ 信用窗 `W ≤ 256`**。
  - *Spoken*: 同时宽窗部分负载下 C H A 仍会爬到二百五十到三百零七。所以最佳实践是三件套并举：零前瞻 u 一 l d p q、合理配核、再加主机信用窗不超过二百五十六。
## B06: 一屏选型口诀：两面墙与两条工程路线 (52.7 s)

*Source: `MRV-155 · MRV-177 · MRV-235 · MRV-245 · MRV-252 · MRV-258`*

- **[0.45–13.28s]** (`MRV-258`) 回顾全貌，两面「十几 M 墙」泾渭分明：墙一是 **`Normal-WB`** 进 `L1D/L2` 引发 `0x58` 死锁，墙二是闭环 **`u4`** 前瞻撞 `TAD` 触发 `EXLMN` 雪崩。
