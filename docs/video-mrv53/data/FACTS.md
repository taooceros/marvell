- **直接通路拓扑（绕过 SDP）**：
  - **去程（Host → Card）**：主机 CPU 用 `MOVDIR64B` 直写 PF BAR4 窗口 15（4 MiB，映射到卡 DRAM 请求环 `reqRing`）。4 核时按 `(seq - 1) % n == i` 分成 `n` 个子环。
  - **回程（Card → Host）三种写回方式**：

    3. **DPI DMA（`DPI1` / `DPI4`，`--dma`）**：卡核提交命令给 DPI DMA 引擎（VF `0000:06:00.1–.4`）写回主机回复环。
- **背景前置（`MRV-35` 旧假硬件参照）**：

- **二进制配对**：
  - `H0`：产品版 `inline_pingpong`（`main` 基线）。
  - `H1`：加入前后双 `lfence` 依赖乘法链忙等（`--host-delay-ns 10 / 20 / 40`）。

## §5 未决问题与后续实验（`MRV-73`、`MRV-74`、`MRV-50` / `MRV-52` / `MRV-56` / `MRV-60`）

- **`MRV-73`（主机限批轮询 `--poll-batch MAX`）**：在卡 4 核直接通路（`WC4 / ST4 / DPI4`，`W = 64 / 1024`）下把 `RingReplies::poll_upto::<MAX>` 暴露为 `--poll-batch MAX`（扫描 `MAX = 1 / 2 / 4 / 8 / 16 / 32` 并配对 `--account-every 64`），检验限制单次跨环轮询条数能否消除 `~1 µs` 轮询尾等待并让卡 4 核跳出慢状态。
- **`MRV-74`（无栅栏真数据依赖链 `2–30 ns` 细步长扫描）**：在单一二进制内用串在 `tsc` 数据路径上的恒等算术依赖链替代 `isb` / `lfence`，扫描 `δ ∈ {0, 2, 5, 10, 15, 20, 30} ns` 直接定位卡 1 核快状态的 `~5 ns` 余量拐点，并在卡 4 核 `δ_card = 0 / 30 / 45 / 60 ns` 跳升态配对开启 `--account-every 64` 实测主机 `busy_poll` 从 `33 ns/条` 回落至 `~14 ns/条` 的过程。
- **`MRV-50` / `MRV-52` / `MRV-56` / `MRV-60`（慢状态与跨 PCIe 争用硬件位置）**：拆解 `13 M/s` 慢状态下每条消息在去程、卡上、回程各停多久（`MRV-50`），卡核停顿跳出慢态是因少读请求环还是回复攒批（`MRV-52`），`W = 32 → 64` 为何从 `18` 掉到 `13 M/s`（`MRV-56`），以及回复是否堆积在主机 IIO（`MRV-60`）。
